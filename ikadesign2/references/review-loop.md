# 检查与回写

使用已有预览、浏览器、截图工具或项目命令。目标是让 `design.md` 的规则在真实页面上产生可见结果。

本文件是检查记录格式、停止规则、机械自检和问题分类的唯一定义。其他文件引用本文件，不重复定义。

## 检查记录

每次检查记录以下字段。记录写入任务记录、临时 Markdown 或评审目录，不写入 `design.md`。

```md
场景：<页面名称>
输入：<固定数据、内容和资源>
视口：<宽度 × 高度>
主题：<light / dark / 未支持>
design.md 版本：<提交哈希或日期>
生成上下文：<新上下文 / 已见源资料的当前上下文>
检查方式：<浏览器、截图、已有命令或人工检查>
结果：<通过 / 失败 / 未执行>
违反：
- <命中 [必须] 或通用不变量的事实>
偏差：
- <命中 [建议] 的事实，以及是否有意>
待确认：
- <无法对应任何规则的发现>
限制：
- <没有检查的范围>
```

不要写“已验证”而不写检查方式。不要用截图差异自动判定品牌质量。

## 一次闭环

1. 选择一个代表页面和固定输入。
2. 使用当前 `design.md` 生成或检查页面。
3. 执行机械自检。
4. 按人工检查顺序检查桌面和窄屏首屏。页面有主题时检查每个已支持主题。
5. 按问题分类记录每个发现。
6. 修复实现错误。
7. 将可迁移的规则缺失写回 `design.md`。
8. 使用相同输入复查一次。
9. 记录复查结果，然后停止。

### 停止规则

一次闭环只修复两类发现：违反 `[必须]` 或通用不变量的项，以及阻塞读者主要任务的项。其他发现记为偏差或待确认，不修复，不迭代。

复查时保留修改前的首个输出。不要挑选最好的一次冒充首次结果。规则影响其他页面类型时，选一个受影响的已有页面复查。不要为凑数量生成整套页面。

复查一次后停止。不做第二轮，除非用户要求。不声称生成已经稳定。

没有渲染环境时，执行文档和代码检查。将视觉结果标为“未执行”。不要用代码存在替代视觉证据。

## 机械自检

机械自检用 DOM、计算样式或产物文本判定，不靠观感。

### 通用不变量

以下项不涉及设计选择。任何页面命中即为违反：

1. 页面恰好有一个 `h1`。
2. `document.scrollWidth` 不超过视口宽度。
3. 同一列的 `th` 与 `td` 文本对齐方式一致。
4. 页面引用的 class、token、字体和资源都能解析到实现。
5. 每个可聚焦元素在聚焦时有可见样式。

### 从 `design.md` 派生的检查

从 `design.md` 的 `[必须]` 规则派生。一条规则同时满足以下两个条件时，转成检查：

- 对象能在 DOM 或产物文本中定位。
- 条件能判定为真或假。

例如，“页面只使用第 5 章列出的 token”可以转成检查。“表格体现证据感”不能转成检查。

不从 `[建议]` 和 `[待确认]` 派生检查。检查清单随品牌走，本文件不预设清单。

### 结果分级

- **违反**：命中 `[必须]` 或通用不变量。必须修复。
- **偏差**：命中 `[建议]`。判断是否有意为之。有意时写一句理由，即通过。无意时修复。

检查不替设计做决定。

## 人工检查顺序

### 读者任务

- 首屏是否说明页面服务的读者任务？
- 主要答案、操作或证据是否先于次要信息？
- 页面是否重复表达同一结论？

### 结构

- 页面类型是否匹配内容密度？
- 主要边缘、标题、内容区和操作区是否按同一网格对齐？
- 是否存在没有任务依据的空栏、空卡片或大面积空白？

### 视觉

- 同类元素是否复用同一字体角色、间距、尺寸和状态？
- 颜色是否表达明确语义？
- 表格、图表和数字是否保留单位、范围、精度和比较基准？
- 组件是否使用 `design.md` 列出的原语？

### 响应式与状态

- 窄屏是否重排，而不是压缩到不可读？
- 是否检查长文本、大数值、空、错误、加载和禁用状态？
- 是否存在横向溢出、被遮挡的焦点或不可访问的操作？

### 文案与安全

- 每条可见文本是否对读者有用？
- 是否泄露路径、内部字段、异常、密钥、调试文本或实现细节？
- 是否将推断写成事实？

## 问题分类

每个问题只选一个主要类别：

- **实现错误**：规则已经写清，但页面没有遵守。修页面。
- **需求问题**：页面的功能、字段、数据或业务行为不符合任务需求。按任务需求修页面，不写入 `design.md`。
- **规则缺失**：`design.md` 没有覆盖某个判断，且有证据表明它是系统规律。提取检查中，来源页面就是证据。生成检查中，需要多个场景出现同一问题。补充 `design.md`。
- **原语缺失**：规则明确，但现有 token、组件或资源无法表达。记录最小实现提案。不要临时发明平行系统。
- **检查环境问题**：预览、数据、字体或工具失败。修环境，或记录未执行。
- **单次模型偏差**：只出现一次且规则已清楚。不修改 `design.md`。

## 规则回写格式

新增规则前，回答：

1. 哪个页面、输入和检查暴露了问题？
2. 这是判断、机械样式还是环境问题？
3. 规则是否在 [design.md 产物约定](design-contract.md) 的“内容边界”以内？不在时按需求问题处理，不回写。
4. 规则适用于哪些页面类型，不适用于哪些页面类型？
5. 修改后能否用同一场景检查？
6. 该规则会不会与已有规则冲突？

把答案写入检查记录，不写入 `design.md`。

合格的回写示例：

```md
[建议] 证据表在桌面内容区占满可用宽度。列多于内容区时保留局部横向滚动，不缩小正文。
适用：证据表、比较表。
不适用：短的两列表单。
```

不合格的回写示例：

```md
让表格更舒服。
```

修改规则后必须复查原场景一次。没有复查时，只能报告“规则已修改，未复查”。
